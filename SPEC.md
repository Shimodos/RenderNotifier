# Render Notifier — уведомления о рендере из 3ds Max в Telegram

Спецификация для старта в Claude Code. Цель: создать репозиторий и довести до рабочего MVP.

## 1. Что делаем

Маленький скрипт, который автоматически загружается вместе с 3ds Max и пишет в Telegram-чат студии:

- когда рендер стартовал: кто, на каком компьютере, какая сцена;
- когда рендер закончился или был отменён: то же плюс длительность.

Рендер запускается через Pulze Scene Manager, но скрипт не должен от него зависеть: он ловит события самого 3ds Max, поэтому работает и при обычном рендере.

Пользователь ничего не запускает руками. Открыл Max, открыл сцену, нажал Render — сообщение ушло.

## 2. Принятые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Куда слать | Telegram Bot API | Бесплатный Teams не даёт официального способа принимать сообщения |
| На чём писать | MAXScript, один .ms файл | Работает во всех версиях Max, не требует установки Python-пакетов |
| Автозапуск | Папка scripts/startup пользователя | Max сам выполняет всё, что там лежит, при старте |
| Отслеживание рендера | callbacks #preRender и #postRender | Штатный механизм Max |
| HTTP | .NET из MAXScript (System.Net) | Уже есть в Max, внешних зависимостей нет |
| Сервер | Нет | Каждый Max сам шлёт запрос в api.telegram.org |
| Конфиг | INI-файл рядом со скриптом | Токен и chat_id не в коде и не в git |

## 3. Допущения, которые надо проверить первыми

Это не факты, а гипотезы. Проверка каждой — отдельный маленький шаг до написания основной логики.

1. **Рендер идёт локально**, в том же Max, где нажали кнопку. Если Pulze отправляет задачу на другие машины (Render Manager, Backburner, Deadline), события сработают на рендер-ноде, а не у художника. Тогда нужна другая схема, см. раздел 9.
2. **Pulze Scene Manager вызывает штатный рендер Max**, и #preRender / #postRender срабатывают. Проверка: зарегистрировать два callback с print в Listener и запустить рендер из Pulze.
3. **При пакетном рендере нескольких setup-ов** события приходят на каждый setup отдельно. Нужно понять, хотим ли мы сообщение на каждый или одно на весь пакет.
4. **Имя текущего setup-а Pulze** можно получить из скрипта. API Pulze не изучен. У Scene Manager есть собственные pre-render и post-render скрипты на уровне setup-а — возможно, это более точный источник. Если не получается — MVP обходится без имени setup-а.

## 4. Архитектура

```
3ds Max (на каждой рабочей станции)
  └─ scripts/startup/render_notifier.ms   <- грузится автоматически
       ├─ читает render_notifier.ini (token, chat_id, опции)
       ├─ #preRender  -> собирает данные -> POST sendMessage
       └─ #postRender -> считает длительность -> POST sendMessage
                                   │
                                   ▼
                    https://api.telegram.org/bot<TOKEN>/sendMessage
                                   │
                                   ▼
                        Групповой чат студии в Telegram
```

## 6. Настройка Telegram

1. В Telegram написать @BotFather, команда /newbot, получить токен.
2. Создать групповой чат студии, добавить туда бота.
3. Написать в чат любое сообщение, затем открыть в браузере `https://api.telegram.org/bot<TOKEN>/getUpdates` и найти chat.id. У групп он отрицательный, у супергрупп начинается с -100.
4. Если в группе включены темы (topics) и нужна отдельная тема «Рендеры» — понадобится ещё message_thread_id.
5. Проверить отправку скриптом tools/test_send.ps1 до того, как трогать Max.

## 7. Конфиг

Файл render_notifier.ini, лежит рядом со скриптом в startup-папке.

```
[telegram]
token=
chat_id=
thread_id=

[options]
enabled=true
notify_start=true
notify_finish=true
min_duration_sec=0
display_name=
timeout_ms=5000
```

- min_duration_sec — не слать сообщение о завершении, если рендер короче порога (тестовые рендеры).
- display_name — как подписывать человека; если пусто, берётся имя пользователя Windows.

## 8. Требования к скрипту

### Данные в сообщении

| Поле | Источник в MAXScript |
|---|---|
| Компьютер | sysInfo.computername |
| Пользователь | sysInfo.username или display_name из конфига |
| Сцена | maxFileName (и maxFilePath при необходимости) |
| Камера | активный вид / viewport.getCamera() |
| Разрешение | renderWidth, renderHeight |
| Кадры | rendTimeType, rendStart, rendEnd |
| Рендерер | classof renderers.current |
| Файл вывода | rendOutputFilename |
| Длительность | разница timestamp между pre и post |
| Setup Pulze | под вопросом, см. допущение 4 |

### Формат сообщений

Старт:
```
🟡 Рендер запущен
Сцена: Kitchen_main.max
Камера: Cam_Front
Компьютер: RENDER-03 (Oleksiy)
1 кадр, 4000×3000, V-Ray
```

Финиш:
```
🟢 Рендер закончен — 1 ч 42 мин
Сцена: Kitchen_main.max
Компьютер: RENDER-03 (Oleksiy)
```

### Обязательное поведение

- **Никогда не ломать и не тормозить рендер.** Любая ошибка внутри callback перехватывается через try/catch и пишется в лог. Нет интернета, неверный токен, нет конфига — Max работает как обычно.
- **Таймаут запроса** не больше значения из конфига. Отправка по возможности асинхронная, чтобы старт рендера не ждал ответа Telegram.
- **TLS 1.2** включить явно через ServicePointManager — в старых версиях Max .NET по умолчанию может выбрать устаревший протокол.
- **UTF-8** для тела запроса: имена сцен и пользователей бывают кириллицей.
- **Повторная загрузка скрипта безопасна**: перед регистрацией callbacks удалять старые по своему id (callbacks.removeScripts id:#renderNotifier).
- **Callbacks глобальные, не persistent** — ничего не записывается в .max файлы.
- **Лог** в %LOCALAPPDATA%\RenderNotifier\render_notifier.log, с ротацией по размеру.
- Одна глобальная struct, никаких россыпей глобальных переменных.

### Что фильтровать

Проверить на практике и отсечь, если срабатывает:
- превью в Material Editor;
- ActiveShade / интерактивный рендер (IPR V-Ray, Corona Interactive);
- Render to Texture.

## 9. Вне MVP

- **Краш Max.** Если Max упал посреди рендера, сообщения о завершении не будет. Решение на потом: внешний сторож (отдельный лёгкий процесс или запланированная задача), который видит, что процесс 3dsmax исчез при незакрытом рендере.
- **Сетевой рендер.** Если допущение 1 неверно: либо ставить скрипт на рендер-ноды, либо ловить момент отправки задачи и статус из менеджера очереди.
- **Токен на каждой машине.** Для студии на 10 человек приемлемо. Если захочется убрать: маленький relay (например, Cloudflare Worker), который хранит токен и принимает запросы от скрипта по общему секрету.
- **Прогресс** по кадрам для анимаций, редактирование одного сообщения вместо двух (editMessageText), превью готовой картинки (sendPhoto).

## 10. План работ

1. Создать репозиторий, структуру из раздела 5, .gitignore, CLAUDE.md.
2. tools/test_send.ps1 — отправить «привет» в чат. Убедиться, что бот и chat_id рабочие.
3. Минимальный .ms: два callback с print в Listener. Положить в startup, проверить допущения 1–3 на реальной сцене с Pulze.
4. Отправка из MAXScript в Telegram: функция send с таймаутом, TLS, UTF-8, try/catch.
5. Чтение INI, сбор данных сцены, форматирование сообщений, длительность.
6. Лог, фильтры лишних срабатываний, min_duration_sec.
7. install.ps1 / uninstall.ps1: найти все папки %LOCALAPPDATA%\Autodesk\3dsMax\* \ENU\scripts\startup и разложить файлы.
8. README для художников. Раскатка на одну машину, затем на всю студию.
9. Исследовать API Pulze ради имени setup-а (допущение 4).

## 11. Критерии готовности MVP

- После установки и перезапуска Max ничего запускать руками не нужно.
- Рендер из Pulze Scene Manager даёт два сообщения в чат: старт и финиш с длительностью.
- Отмена рендера даёт сообщение о завершении (в идеале — с пометкой «отменён», если это удаётся отличить).
- Без интернета Max рендерит как обычно, в логе запись об ошибке.
- Токен не попадает в git.

## 12. Среда

- Windows, 3ds Max (версии уточнить — от них зависит версия .NET и путь к startup).
- Рендерер уточнить (V-Ray / Corona) — влияет на фильтрацию интерактивного рендера.
- Pulze Scene Manager — версию уточнить.
